# Web Remote — веб-интерфейс для Audacious
![main window](img/main.png?raw=true "main window")

General-плагин для Audacious 4.x: встроенный HTTP-сервер и одна страница,
с которой можно управлять плеером из браузера (в том числе с телефона).

- что сейчас играет: название, исполнитель, альбом, обложка, позиция, перемотка;
- управление: играть/пауза, стоп, вперёд/назад, громкость, случайный порядок,
  повтор плейлиста, повтор текущего трека;
- эквалайзер: включение, предусиление, 10 полос, предустановки (сохранённые
  в Audacious и несколько встроенных);
- **«Убрать текущий»** — удаляет играющий трек из плейлиста (файл на диске не
  трогается) и продолжает со следующего;
- вкладки плейлистов: переход к любому листу (он же становится активным в окне
  Audacious), запуск листа, создание, переименование, очистка, удаление;
- список треков: щелчок — играть, ✕ — убрать из плейлиста, очередь, поиск,
  добавление файла/папки/адреса;
- **«Вернуть»** — отмена удаления трека или очистки плейлиста (до 30 шагов,
  также Ctrl+Z); трек возвращается на прежнее место;
- **загрузка файлов** с телефона или другого компьютера (кнопка «Загрузить»
  или перетаскивание на страницу): принимаются все форматы, которые умеет
  Audacious (или список из настроек) — файл сохраняется на компьютере с Audacious и добавляется в плейлист;
- **скачивание трека** на своё устройство — кнопка у каждой записи и у
  играющего трека (только файлы с диска, не сетевые потоки): оригинальный
  файл или **MP3** — трек прогоняется через Audacious, поэтому в MP3
  превращаются и трекерные модули (xm, s3m, it, mod…), и MIDI, и всё остальное,
  что он умеет играть;
- **трансляция звука в MP3**: кнопка «Слушать здесь» на странице или адрес
  `/stream.mp3` в любом плеере; галочка «поток» у ползунка громкости
  переключает его на громкость трансляции — свою в каждом браузере.

## Сборка и установка

    make
    sudo make install      # копирует оба модуля в каталог плагинов Audacious

Модулей два: `General/webremote.so` (сервер и страница) и
`Effect/webremote-stream.so` (отвод звука для трансляции).

Нужны g++, make, curl. Пакет `audacious-dev` не обязателен: если его нет,
Makefile скачает исходники той же версии Audacious и возьмёт из них заголовки.

После установки перезапустите Audacious и включите плагин:
**Настройки → Модули → Общие → Web Remote**. Интерфейс: <http://localhost:8421/>.

Попробовать без установки в систему (отдельный экземпляр со своими настройками):

    make sandbox           # http://localhost:8422/

## Настройки

| Параметр | По умолчанию | |
|---|---|---|
| Порт | 8421 | |
| Доступ с других устройств | выкл. | выкл. — только `127.0.0.1`; вкл. — все интерфейсы |
| Пароль | пусто | HTTP Basic, логин любой |
| Трансляция звука в браузер (MP3) | выкл. | включает эффект «Web Remote: трансляция звука» |
| Битрейт | 192 кбит/с | применяется со следующего трека |
| Разрешить скачивание треков | вкл. | |
| Битрейт при скачивании в MP3 | 256 кбит/с | |
| Разрешить загрузку файлов | вкл. | |
| Папка для загруженных файлов | `~/Music/Audacious Web` | |
| Разрешённые расширения | пусто | пусто — всё, что умеют включённые модули ввода |

Соединение не шифруется, поэтому открывать порт стоит только в домашней сети
и лучше с паролем.

## Трансляция

Транслируется то, что играет Audacious: перемотка и смена треков слышны
в браузере, с задержкой в пару секунд (буфер браузера). Сервер отдаёт
звук вровень с колонками, и задержка не растёт при переключениях. Поток всегда 44,1 кГц
стерео; на паузе и при остановке идёт тишина. Звук берётся до регулятора
громкости Audacious, так что на компьютере громкость можно убрать в ноль
(при программной регулировке громкости) и слушать только в браузере.
Кодирование идёт, только пока есть слушатели.

Нужна библиотека `libmp3lame.so.0` (пакет `libmp3lame0`, обычно уже стоит
вместе с ffmpeg); заголовки для сборки не требуются.

## За nginx

Адреса на странице относительные, поэтому достаточно одного `location`:

    location /player/ {
        proxy_pass http://127.0.0.1:8421/;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $http_host;
        proxy_buffering off;            # трансляция без задержки
        proxy_read_timeout 1h;
        client_max_body_size 2g;        # загрузка файлов (по умолчанию 1 МБ)
        proxy_request_buffering off;
    }

## HTTP API

`GET /api/status`, `GET /api/playlist?pl=N`, `GET /api/art`, `GET /api/download?pl=N&entry=M`; команды — `POST /api/<команда>`
с параметрами формы:

`play` `pause` `playpause` `stop` `next` `prev` `seek(time)` `volume(value)`
`shuffle` `repeat` `repeat_one` `eq(active, preamp, bands | band+value)` `remove_current` `undo` `playlist_new(title)` и команды над листом `pl`:
`activate` `playlist_play` `playlist_rename(title)` `playlist_delete` `playlist_clear`
`add(uri)` `jump(entry)` `remove(entry)` `queue(entry)`.

    curl -X POST localhost:8421/api/remove_current
    curl -X POST --data-binary @song.mp3 'localhost:8421/api/upload?pl=0&name=song.mp3'

Записи адресуются номерами, поэтому клиент может передать `sserial` из
последнего ответа: если состав плейлистов с тех пор изменился, сервер ответит 409
вместо того, чтобы удалить не тот трек.
